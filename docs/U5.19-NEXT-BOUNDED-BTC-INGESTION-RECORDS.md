# U5.19 Next.js Bounded BTC Ingestion Records

**Status:** Implemented locally on 2026-10-29.  
**Scope:** Close the remaining bounded B1 web inspection work for ingestion outcomes, candle gaps, and raw-row provenance.

## Contract

- `GET /v1/btc/history/datasets/<revision>/manifests/<manifest-id>/outcomes` pages up to 100 ordered outcome rows with an exclusive `after_outcome_index` cursor.
- The corresponding `/gaps` route pages the selected hash-verified manifest's sorted gap records with an exclusive `after_start_time_ms` cursor.
- The `/provenance` route pages unique `(raw_page_sha256, row_index)` records with a paired exclusive hash/row cursor. Identical raw pages remain deduplicated by the existing provenance key.
- Every route binds the manifest ID to the requested dataset revision, uses the configured HistoryStore, opens its DuckDB catalog read-only, rejects caller-selected roots and unknown/duplicate query fields, and creates no missing storage.
- Outcomes verify the manifest file and compare the complete stored status counts to the manifest. Each displayed row is joined to its raw provenance fingerprint. Reason previews are capped at 512 characters.
- Gap records come from the one manifest whose size is capped at 8 MiB and whose SHA-256 matches the catalog. Invalid, unsorted, or count-mismatched gap entries fail closed.
- Provenance previews are capped at 512 ASCII characters. The server hashes each full stored payload when it is no larger than 256 KiB and requires that hash to match its source-record fingerprint; oversized or mismatched rows fail closed. No full payload is returned.
- Filesystem paths and caller-controlled roots are never returned. These GET views do not ingest, replay, or mutate data.

## Design

The manifest detail page links to outcomes, gaps, and raw provenance under
`/datasets/<revision>/manifests/<manifest-id>/<record-type>`. Each server-rendered
page has strict cursor parsing, an explicit total, a 1–100 page size, and a
contained keyboard-scrollable table. Provenance is shown as escaped text with a
visible truncation marker. The existing dark operator styles are reused; no
new component dependency or animation was added.
