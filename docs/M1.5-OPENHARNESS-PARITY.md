# M1.5: OpenHarness adapter parity

**Status:** fixture/runtime-double verified; real OpenHarness execution remains unverified and the runtime is not promoted to production ownership.

## Harness scope

`market_os/orchestration/` defines the root-owned `OrchestrationAdapter` protocol, the OpenHarness-shaped adapter, and a parity report. The adapter uses the existing `MarketWorkflow`, contracts, providers, and `RunStore`; it does not import OpenHarness or add it as a dependency.

Run the harness with the current dependency-light environment:

```text
python -m market_os.orchestration.parity
```

The default task is the shared fixture: research three US ETFs, cite timestamped evidence, run a deterministic backtest, create a paper order plan, apply risk checks, and persist the run trace.

## Current parity result

The fixture runtime reports these behaviors as exact matches:

- research, backtest, order-plan, and risk result payloads;
- paper-only task and order-plan behavior;
- event order and explicit UTC timestamps;
- content-addressed artifact SHA-256 values;
- artifact lineage;
- evidence IDs and research citations;
- contract JSON round trips;
- workflow result shape used by CLI/API callers;
- cooperative cancellation;
- provider failure terminal status and error message;
- idempotent replay;
- restart inspection;
- live task rejection.

## Required translations

OpenHarness-shaped session/tool names are translated at the adapter boundary:

Task creation is also a translation boundary: stable objective, symbols, date range, execution mode, idempotency key, and API version fields must match; runtime-owned task IDs and creation timestamps may differ.

| OpenHarness-shaped event | Market OS event |
|---|---|
| `ToolExecutionStarted` | `tool.started` |
| `ToolExecutionCompleted` | `tool.completed` |
| `AssistantTurnComplete` | `agent.turn.completed` |
| `ErrorEvent` | `agent.error` |
| `StatusEvent` | `runtime.status` |
| `CompactProgressEvent` | `runtime.progress` |
| adapter `session.started` | `run.started` |
| adapter `session.completed` | `run.completed` |
| adapter `session.rejected` | `run.rejected` |
| adapter `session.cancelled` | `run.cancelled` |
| adapter `session.failed` | `run.failed` |

The OpenHarness source also uses asyncio task cancellation for gateway/session interruption. The fixture adapter maps the dependency-free workflow's cooperative cancellation checkpoint to `session.cancelled`. The adapter records `actor="openharness"` on translated events. Runtime-specific fields stay inside the internal event object and are not added to domain contracts.

## Unsupported and unverified behavior

- The actual OpenHarness child runtime was not imported or executed. The fixture runtime is an explicit test double with `runtime_verified=false`.
- Provider credentials, external market data, model calls, and broker calls are not used.
- Mid-provider cancellation, external session resume, and production storage semantics remain unverified.
- CLI/API compatibility is currently checked at the shared result and inspection shape; a real OpenHarness gateway transport still requires an adapter test.

## Promotion gate

OpenHarness cannot be promoted from provisional to production owner yet. Promotion requires a real-runtime fixture-parity run in an isolated environment, with the same checks passing for lifecycle, failure, cancellation, restart, idempotency, artifact lineage, contract serialization, and paper-only enforcement. A separate approval is required before any real provider is connected.
