# B4.7 Malformed Snapshot Recovery

**Status:** Implemented locally on 2026-10-27 as a synthetic, paper-only hardening slice.

**Purpose:** Make recovery fail closed with a stable broker error when an event's persisted resulting snapshot contains malformed order or fill records.

## Scope

- Guard snapshot restoration during ledger recovery.
- Normalize missing fields, invalid record shapes, invalid numeric values, and invalid order/fill construction into `BrokerRejected("ledger resulting snapshot is malformed")`.
- Preserve the existing snapshot fingerprint, ledger chain, identity, cursor, checkpoint, and idempotency checks.

## Public seam and evidence

The public seam is `B41Broker.open()` / `B41Broker.recover()`. Regression coverage is in [test_b41_broker.py](../market_os/tests/test_b41_broker.py), covering malformed persisted order and fill records with a self-consistent snapshot fingerprint and event fingerprint.

## Boundaries

B4.7 does not repair or skip a malformed snapshot, change the ledger format, add a new persistence backend, add partial fills or expiry, expose mutation API routes, share portfolios, call providers, use live data, trade, deploy, commit, or push. The B4.1 contract remains the source of truth for broader replay and schema migration policy.
