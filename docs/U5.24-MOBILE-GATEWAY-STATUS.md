# U5.24 Mobile Gateway Status

**Status:** Implemented and verified locally on 2026-10-29.

**Scope:** Keep local/read-only boundaries and gateway availability visible on narrow operator views.

## Contract

- Below 560 CSS pixels, show gateway availability in the compact header because the sidebar service card is hidden.
- Keep the local-only and read-only boundary visible in the same header.
- Preserve the desktop header badges and sidebar service card.
- Keep the server-rendered shell local-only, GET-only, paper-only, and read-only. Add no network path, dependency, or animation.
- Expose status as text and an accessible status role; color remains supplementary.

## Design review

| Before | After | Why |
| --- | --- | --- |
| Gateway state appeared only in the sidebar card, which disappears below 560px. | A compact header pill shows the current gateway state below 560px. | Operators can still see availability without opening navigation or inferring state from color. |
| Separate local-only and read-only pills used desktop header space. | Mobile combines the two boundary labels into `Local · read only`. | The safety boundary stays visible at narrow widths with less header clutter. |

## Implementation

`AppShell` adds the compact mobile boundary and gateway status. The status uses the existing `available`, `unavailable`, and `unknown` states, includes the loopback address in its accessible label, and has `role="status"`. Responsive rules keep the new items hidden above 560px; the existing desktop status card and separate boundary labels remain in place. The dashboard design rules record the breakpoint behavior.

## Verification

- Next.js typecheck passed.
- Optimized Next.js production build passed.
- Production browser review checked 320, 375, 560, 561, 768, and 1440 CSS pixel breakpoints. At narrow widths the header displays both gateway state and local/read-only status while the sidebar card is hidden; above the breakpoint the sidebar card is visible. No page-level horizontal overflow was observed.
- At 320px, Playwright confirmed the visible status text, `role="status"`, loopback address label, and boundary text. The production browser console reported zero errors.
- The gateway was unavailable during this browser pass; the rendered state was accurately reported as unavailable. Available and unknown states remain the same closed prop values already used by the shell.
- Screenshot: `output/playwright/u5-24/mobile-gateway-320.png` (local review artifact; not part of the source commit).
- No DirectAdmin deployment or connected access was attempted.

Machine-readable evidence is in `docs/evidence/u5-24-mobile-gateway-status.json`.
