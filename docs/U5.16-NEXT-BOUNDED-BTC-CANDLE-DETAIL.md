# U5.16 Next.js Bounded BTC Candle Detail

**Status:** Implemented locally on 2026-10-29.  
**Scope:** Add a bounded, read-only candle page to the U5.15 BTC dataset registry.

## Contract

- `GET /v1/btc/history/datasets/<revision>/candles` accepts `limit` 1–100
  (default 25) and optional exclusive `after_open_time_ms`.
- The cursor must match a stored candle open time. Results are strictly ordered
  by `open_time_ms`; the next cursor is the final returned candle when another
  page exists.
- The endpoint uses only the gateway-configured HistoryStore. It rejects
  arbitrary store roots and all unsupported or duplicate query parameters.
- Existing catalogs open read-only. Missing revisions return 404; malformed
  catalog or Parquet data returns an integrity error. Path-resolution failures,
  including symlink loops, are normalized to a generic integrity response.
- The endpoint verifies the canonical relative Parquet path and stored file
  hash before reading rows. Hashing uses bounded chunks; the response contains
  at most 100 rows and bounded decimal strings, with no file paths or provenance.
- The server-rendered `/datasets/<revision>` page shows exact stored numeric
  strings, UTC timestamps, the dataset fingerprint, and GET-only pagination.
  It keeps the wide candle table inside a labelled keyboard-scrollable region.
- Dataset and candle-page links disable background prefetch so passive viewport
  observation does not trigger Parquet hashing requests.
- A page-level Parquet hash check does not replace canonical replay. Replay is
  still required to verify the data against the dataset fingerprint.

## Design

The detail route extends the existing dark, dense, local-read-only dataset
registry. It adds a registry link, dataset coverage/fingerprint metadata, and a
seven-column table with first-page/next-page navigation. The page remains a
server component and adds no client state, charting, decorative motion, external
font, provider call, or ingestion action.

## Verification

- Focused Python API/HistoryStore tests cover bounded pages, exclusive cursor
  order, query rejection, no caller-selected root, no path fields, exact decimal
  lexemes, missing cursors, path/hash tampering, symlink-loop errors, and
  read-only catalog access (39 tests passed).
- Next.js typecheck and production build.
- Browser smoke covers populated detail navigation, next-page links, desktop
  and 375px mobile layout, and zero browser-console errors.
- Spec and security reviews closed the findings on symlink-loop path handling
  and the evidence test count; no actionable findings remain.
- Machine-readable results are recorded in
  `docs/evidence/u5-16-next-bounded-btc-candle-detail.json`.

## Remaining limits

- File hashing remains linear in Parquet bytes on every page; it uses bounded
  memory and preserves the existing integrity boundary.
- Dataset manifests, outcomes/provenance/gaps, and B2/B3 experiment/report
  views still need separate bounded contracts before exposure.
- Connected deployment remains gated by U5.5 target, identity, isolation, and
  operations decisions.
