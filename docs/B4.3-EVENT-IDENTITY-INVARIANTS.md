# B4.3 Event Identity Invariants

**Status:** Implemented locally on 2026-10-26 as a synthetic, paper-only hardening slice.

**Purpose:** Enforce the B4.1 contract's unique synthetic market-event identity at the public event-processing seam while preserving B4.1 persistence and B4.2 recovery behavior.

## Scope

- Reject a market event whose `event_id` is already present in the processed event cursor.
- Reject persisted recovery state whose event cursor contains duplicate IDs.
- Leave snapshot and ledger bytes unchanged when a duplicate event is rejected.
- Preserve strictly increasing event-time validation and deterministic replay.

## Public seam and evidence

The public seam is `B41Broker.process_market_event()`. Regression coverage is in [test_portfolio_broker.py](../market_os/tests/test_portfolio_broker.py): a later-timestamp retry of an existing event ID fails closed and does not mutate the snapshot or ledger.

## Boundaries

B4.3 does not add partial fills, expiry, shared portfolios, a new persistence backend, semantic event reduction, mutation API routes, provider access, live data, trading, or deployment. The B4.1 contract remains the source of truth for broader command and recovery semantics.
