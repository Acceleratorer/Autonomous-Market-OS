# M2.7: CI/CD foundation

The fusion repository has two GitHub Actions workflows:

- `.github/workflows/ci.yml` runs on pushes to `main` and pull requests.
- `.github/workflows/security.yml` runs on the same events.

They require no model, broker, market-data, document-provider, or child-repo
secrets. Tests do not make external model/provider calls. CI package
installation may access the package index; adapter tests and runtime checks
remain offline.

## Checks

CI uses Python 3.12, installs the local project and pytest, and runs:

- unit tests (`not integration`);
- integration-marked offline tests;
- the full project test suite;
- `compileall`;
- evidence JSON validation;
- CLI/API and default-offline adapter smoke tests;
- `git diff --check`.

The security workflow also runs `pip check`, a high-confidence secret-pattern
scan over current executable/project inputs under `market_os/`, `scripts/`,
and `.github/` (historical evidence and preserved local probes are excluded), evidence validation,
model-boundary tests, compilation, and diff checks. The scanner only detects
high-confidence provider key/private-key patterns to avoid treating synthetic
fixture strings as credentials.

## Local reproduction

```text
python -m pip install -e . pytest
python -m pytest -q -m "not integration"
python -m pytest -q -m integration
python -m pytest -q
python -m compileall -q market_os
python scripts/ci_checks.py validate-evidence
python scripts/ci_checks.py secret-scan
git diff --check
```

There is no live-model CI workflow. A future live smoke requires separately
approved provider/model, credential, data sent, retention, allowed destination,
request count, token/output ceiling, and spend. M2.7 does not deploy, publish,
release, or configure production infrastructure.
