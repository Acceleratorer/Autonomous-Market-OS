# U5.9 Bounded Local Portfolio Inspection

**Status:** Implemented and verified locally on 2026-10-29.  
**Scope:** Bound the portfolio history returned to the local web surfaces while
preserving the existing B4 domain owner and read-only boundary.

## Decision

Add `GET /v1/b4/portfolios/{portfolio_id}/inspection` as the versioned aggregate
read used by both local browser surfaces. It opens and recovers the broker once
per HTTP request, returns a compact summary, and pages orders and risk outcomes
independently. Existing resource routes remain available for local compatibility.

The aggregate returns `market-os.b4-portfolio-inspection@v1`. Each history page
is newest-first and uses an exclusive cursor:

- `order_limit` and `risk_limit` accept integers from 1 through 100.
- `order_before_id` selects orders strictly older than the referenced order.
- `risk_before_sequence` selects outcomes with a lower ledger sequence.
- Unknown or repeated query parameters, malformed cursors, and invalid limits
  return HTTP 400.
- The Next.js boundary validates page sizes and decimal sequence strings before
  mapping response arrays. The compatibility shell announces page changes with
  polite live status text.
- Orders project only the fields needed by the table. Risk records project a
  decimal sequence string, event kind, and stable reason code; raw ledger
  payloads are not returned by this endpoint.
- The compact summary exposes `market_event_count` instead of the full event ID
  cursor.

The Next.js operator and the compatibility HTML shell each load the aggregate
once. Both surfaces provide latest/older navigation for orders and risk records;
changing one page preserves the other page's cursor.

## Verification

- Focused broker pagination and operator/API tests pass.
- The Next.js TypeScript check and optimized production build pass.
- A production-mode browser smoke against a temporary synthetic portfolio
  verified 27 orders as pages of 25 and 2, and 10 outcomes as pages of 8 and 2.
- The two cursors remain independent in Next.js and the compatibility shell.
- At 375px, the document fits within the viewport; the desktop/mobile smoke had
  no browser console errors. Screenshots are in `output/playwright/u5-9/`.
- Page limits and cursor parsing are checked at the broker and HTTP boundaries.

Machine-readable results are in `docs/evidence/u5-9-bounded-local-inspection.json`.

## Limits and next gates

- Broker opening still performs validated ledger recovery, and each risk-page
  read scans the append-only ledger to find the requested window. Order and
  risk list lengths are bounded; the aggregate response can still grow with
  membership and reservation cardinality, while recovery and risk-page work
  remain linear in ledger size.
- The aggregate still returns complete genesis membership and current
  reservation rows because those are existing identity/capacity views. Their
  domain cardinality is not capped by this milestone. U5.10 adds a v2 aggregate
  for the current browser surfaces; this historical v1 contract remains
  unchanged for local compatibility.
- The legacy `/risk` resource still returns its complete history for local
  compatibility. Do not expose that route or the new endpoint through a shared
  service until the old contract is retired or bounded and the U5.5 identity,
  isolation, rate-limit, audit, backup, rollback, and operator-access gates are
  resolved.
- This milestone does not choose a connected deployment target or identity
  provider. It adds no authentication, public listener, mutation route,
  credential, provider call, or live venue.
- B4 retention deletion and schema transformation remain separate contracts.

No public deployment or external portfolio access is authorized by U5.9.
