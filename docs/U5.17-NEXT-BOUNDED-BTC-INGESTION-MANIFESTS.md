# U5.17 Next.js Bounded BTC Ingestion Manifests

**Status:** Implemented locally on 2026-10-29.  
**Scope:** Add bounded read-only inspection for B1 ingestion-run manifests to the U5.15/U5.16 local BTC dataset surfaces.

## Contract

- `GET /v1/btc/history/datasets/<revision>/manifests` accepts `limit` 1–100
  (default 25) and an optional exclusive `after_manifest_id` cursor. The cursor
  must identify a manifest attached to the requested dataset revision.
- `GET /v1/btc/history/datasets/<revision>/manifests/<manifest-id>` returns
  fixed manifest metadata only when the manifest ID belongs to that revision.
- Both endpoints use the gateway-configured HistoryStore, reject caller roots,
  open an existing DuckDB catalog read-only, and invoke no ingestion, provider,
  broker, or mutation path.
- Manifest file paths are derived from validated IDs, resolved inside the
  configured manifest directory, read with an 8 MiB cap, and checked against
  the catalog SHA-256 before parsing.
- Responses contain fixed scalar metadata, outcome counts, and counts for raw
  page fingerprints, gaps, and parent revisions. They omit paths, full arrays,
  raw records, and provenance payloads.
- Malformed catalog rows, escaped/missing files, oversized files, hash mismatch,
  malformed JSON, and unsupported display values fail closed as integrity
  responses. Canonical replay remains required for dataset validation.
- The Next.js surface adds a paged ingestion-run list and a manifest detail page
  under `/datasets/<revision>/manifests`. Links disable background prefetch so
  opening the list does not hash all manifest files.

## Design

The pages reuse the local operator's dark, dense, keyboard-scrollable inspection
patterns. The run list shows request ranges, request counts, and manifest hashes.
The detail page groups lineage and runtime metadata, fingerprints, outcome
counts, and bounded collection counts. The raw page-hash, gap, and parent arrays
remain available to local CLI/domain tools; this web slice does not copy them
into the browser response. No chart, animation, client state, or new UI library
is introduced.

## Verification

The focused API/HistoryStore group passed 41 tests. It covers paging, cursor
validation, dataset binding, read-only catalog access, fixed response shape,
omitted arrays/paths, malformed-query rejection, file-hash mismatch, oversize
rejection, and configured-root error normalization. Next.js typecheck and
production build passed. Desktop/375px mobile browser smoke verified the
registry → dataset → manifest list → manifest detail flow, next-page navigation,
contained table scrolling, and zero console errors. Machine-readable results are recorded in
`docs/evidence/u5-17-next-bounded-btc-ingestion-manifests.json`.

## Remaining limits

- Manifest details above 8 MiB are deliberately not rendered; local CLI/domain
  inspection remains available for those records.
- B2/B3 experiment/report views were added in U5.18. Outcome, gap, and raw
  provenance pages were added in [U5.19](U5.19-NEXT-BOUNDED-BTC-INGESTION-RECORDS.md).
- Connected deployment remains gated by U5.5 target, identity, isolation, and
  operations decisions.
