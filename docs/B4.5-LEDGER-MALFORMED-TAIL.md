# B4.5 Malformed Ledger Record Recovery

**Status:** Implemented locally on 2026-10-27 as a synthetic, paper-only hardening slice.

**Purpose:** Make recovery fail closed with a stable broker error when the append-only JSONL ledger contains a torn, undecodable, or non-object record.

## Scope

- Convert invalid UTF-8 and invalid JSON ledger lines into `BrokerRejected("ledger record is malformed")`.
- Reject JSON values that are not ledger record objects with the same typed recovery failure.
- Preserve the existing sequence, identity, fingerprint, snapshot, checkpoint, and idempotency validation after parsing.

## Public seam and evidence

The public seam is `B41Broker.open()` / `B41Broker.recover()`. Regression coverage is in [test_b41_broker.py](../market_os/tests/test_b41_broker.py), including a truncated JSON tail, invalid UTF-8, and a JSON array appended to the ledger.

## Boundaries

B4.5 does not repair or truncate files, skip malformed entries, add a new persistence backend, add partial fills or expiry, expose mutation API routes, share portfolios, call providers, use live data, trade, deploy, commit, or push. The B4.1 contract remains the source of truth for broader recovery and retention policy.
