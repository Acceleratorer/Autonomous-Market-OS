# M2.6: Bounded optional model-adapter plan

Status: plan only. This document authorizes no model call, credential, network
access, dependency installation, or provider integration.

## Recommendation

Use OpenAI's Responses API with `gpt-6.1-sol` for the first optional adapter.
OpenAI's current model guidance describes Sol as the balanced lower-cost model
for complex professional work, and its model page documents Responses API,
Structured Outputs, text input/output, and usage pricing. The Responses API
documentation recommends Responses for new projects and exposes structured
output through the Responses `text.format` shape.

Primary documentation reviewed:

- [Latest model guidance](https://developers.openai.com/api/docs/guides/latest-model.md)
- [GPT-6.1 Sol model page](https://developers.openai.com/api/docs/models/gpt-6.1-sol.md)
- [Responses API migration guide](https://developers.openai.com/api/docs/guides/migrate-to-responses.md)
- [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs.md)
- [Data controls](https://developers.openai.com/api/docs/guides/your-data.md)

This is a recommendation, not approval. Provider access, account entitlement,
data-retention posture, regional processing, legal review, and spend approval
remain unresolved decisions.

## Adapter seam and output contract

Reuse `market_os.model_summary.SummaryModelProvider`:

```text
generate(SummaryRequest, ResearchSynthesis) -> ModelOutput
```

The adapter would serialize the existing normalized synthesis, including claim
IDs, passage IDs, document metadata, source/provider identity, published and
retrieved timestamps, content hashes, exact passage text, and lineage artifact
IDs. It would ask the model for structured `GeneratedStatement` records only:

- `statement_id`
- `text`
- `classification`: `supported`, `inference`, or `unsupported`
- `citation_ids`
- `support_ids`
- `document_ids`
- `evidence_quotes`
- optional `confidence`

The adapter never decides whether a statement is publishable. It maps the
provider response to `ModelOutput`; the existing gate validates exact quotes,
citations, supports, document lineage, hashes, output size, secret-like text,
and classified rendering. Rejected output publishes no model text. A timeout or
provider error preserves deterministic M2.3 synthesis through the existing
fallback path.

## Explicit opt-in configuration

Names only; no values are added in M2.6:

- `MARKET_OS_SUMMARY_PROVIDER`
- `MARKET_OS_OPENAI_MODEL`
- `OPENAI_API_KEY`
- `MARKET_OS_OPENAI_REQUEST_TIMEOUT_SECONDS`
- `MARKET_OS_OPENAI_MAX_RETRIES`
- `MARKET_OS_OPENAI_MAX_INPUT_CHARS`
- `MARKET_OS_OPENAI_MAX_OUTPUT_TOKENS`
- `MARKET_OS_OPENAI_MAX_COST_USD`
- `MARKET_OS_OPENAI_STORE_RESPONSES`

The provider must be selected explicitly on the cited LightRAG workflow. The
default remains deterministic M2.3 synthesis. A missing key, unsupported model,
or missing approval fails closed with an actionable configuration error; it
does not fall back silently to another provider.

## Network, credentials, and redaction boundary

- Allowed outbound destination: OpenAI's documented HTTPS API endpoint for the
  Responses API only. No web search, file search, remote MCP, market-data, or
  document-provider tools are enabled.
- Data sent: the selected synthetic or approved research synthesis and the
  bounded task objective. Do not send local filesystem paths, environment
  variables, secrets, broker state, portfolio credentials, or unrelated
  documents.
- Credential source: `OPENAI_API_KEY` or an approved secret manager. Never put
  it in task payloads, artifacts, exception text, or logs.
- Logs record provider/model identity, request fingerprint, response ID only if
  approved for retention, bounded status/error class, usage, and latency. They
  redact authorization headers, prompt text, response text, and secret-like
  patterns.
- `store` should be explicitly disabled unless data-retention approval allows
  provider-side response storage. The provider's current data-retention and
  regional-processing terms must be rechecked before implementation.

## Bounds

- Reject input above `MARKET_OS_OPENAI_MAX_INPUT_CHARS` before the request.
- Request a bounded structured output with no more than the configured output
  token limit; reject a response above `MAX_MODEL_OUTPUT_CHARS`.
- Use one request deadline from the existing provider execution boundary.
- Permit at most one bounded retry for transient transport/5xx/rate-limit
  failures. Never retry validation failures or authentication errors.
- Require non-negative input/output token usage when the provider reports it;
  preserve `null` when usage is unavailable.
- Require a provider-reported or independently documented cost estimate before
  any promotion decision. Budget overrun rejects the request before publication.
- Keep the model adapter outside the Market OS risk and order-plan authority.

## Cache, provenance, and replay

Cache keys must include provider, model snapshot, prompt version, objective,
normalized synthesis fingerprint, and adapter contract version. A cached
response is usable only when its stored response fingerprint, usage, model
identity, retrieval/synthesis lineage, and validation result recompute exactly.

Persist cached response provenance as a model-summary artifact child of the
cited-research artifact. Replaying a recorded response must never call the
provider and must reproduce the same output/summary fingerprint. A live call
must not overwrite an existing recorded response with a different provider,
model snapshot, prompt version, or synthesis fingerprint.

## Tests and live smoke

Offline recorded-response tests come first:

1. Feed recorded valid, paraphrase, unsupported, missing-citation,
   cross-run, corrupt-hash, prompt-injection, secret-like, excessive-output,
   timeout, malformed, and provider-error responses through the adapter seam.
2. Assert the existing gate, deterministic fallback, fingerprints, usage
   unknown semantics, artifact lineage, redaction, paper-only state, CLI/API
   inspection, and restart replay.
3. Run the full synthetic M2.5 corpus without network access.

Optional live smoke, only after explicit human approval, would send one
synthetic `fully-supported` corpus case through one `gpt-6.1-sol` Responses API
request with storage disabled, no tools, bounded input, bounded output, and no
retry. The smoke must assert that the returned structured statements pass the
existing citation gate, then discard provider response text except for the
approved content-addressed test artifact. With the documented standard Sol
rates and a 4,000-token input / 512-token output cap, the expected maximum is
under **$0.02 USD** for one request; the configured budget guard must reject a
higher estimate. Current pricing and retention terms must be revalidated before
running it.

No live smoke is part of M2.6 verification.

## Licensing and retention questions

Before implementation approval, confirm from current provider terms:

- whether synthetic research text may be sent and retained;
- default response storage and deletion behavior;
- zero-data-retention and regional-processing eligibility for the selected
  account and endpoint;
- whether request/response content is used for training under the intended
  account type;
- applicable enterprise, privacy, and cross-border data terms;
- model snapshot availability and change-notification policy;
- pricing for input, cached input, output, retries, and regional processing;
- redistribution and artifact-retention rights for generated output.

## Approval and stop condition

M2.6 does not implement the adapter. Implementation requires explicit approval
of the provider/model, endpoint/data boundary, credential mechanism,
retention/region posture, and maximum spend. If any one remains unresolved,
keep the deterministic provider as the default and continue recorded-response
fixture work without a live model.
