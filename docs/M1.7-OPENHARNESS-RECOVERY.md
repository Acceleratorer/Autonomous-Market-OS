# M1.7: OpenHarness recovery probes

**Date:** 2026-10-13
**Decision:** OpenHarness remains **Provisional**.

## Scope

The probe drives the same Market OS workflow used by the dependency-free
reference path: research three US ETFs from local timestamped fixtures, run the
deterministic backtest, create a paper order plan, apply risk checks, and persist
the run trace. The child runtime is executed only through an explicitly selected
isolated interpreter. No provider credentials, market-data network calls,
broker calls, or live execution are used.

The machine-readable report is generated with:

```text
python -m market_os.orchestration.parity \
  --root <isolated-output> \
  --openharness-python <isolated-venv>/Scripts/python.exe \
  --recovery-output <isolated-output>/recovery.json
```

## Runtime evidence

The isolated OpenHarness runtime directly verified:

- provider failure becomes an observable `ErrorEvent`;
- tool exceptions, malformed tool returns, and contract validation failures are
  converted into observable tool errors while the query continues;
- persistence exceptions surface from session snapshot writes;
- a Market OS event persistence failure leaves the run in `running` rather than
  normalizing it to a terminal failure;
- cancellation before start and during provider/tool work raises an observable
  `CancelledError`;
- cancellation after completion and repeated cancellation are idempotent;
- duplicate request replay, artifact lineage, terminal event persistence,
  terminal status, and paper-only task rejection remain correct through the
  Market OS reference store;
- two in-process teammates preserve distinct agent identities, a shared parent
  session identity, shared run identity, and deterministic completion ordering.

The committed machine-readable report is
[`docs/evidence/m1.7-openharness-recovery.json`](evidence/m1.7-openharness-recovery.json).
The probe code can regenerate it in any isolated environment.

## Blockers

These behaviors were directly observed as unsupported or incomplete and remain
promotion blockers:

1. Artifact persistence has no cooperative cancellation hook.
2. A cancelled in-flight query has no runtime-native resume protocol after
   restart.
3. Restart during a running task has no mid-turn snapshot guarantee.
4. Partial teammate failure is swallowed by the in-process teammate loop and
   has no final aggregation event.
5. Duplicate teammate results are not deduplicated by a runtime-native result
   contract.
6. Final multi-agent aggregation does not preserve shared artifact and failure
   semantics through a documented runtime contract.
7. Deployment and dependency requirements have not been proven in a deployment
   environment.

The fixture adapter and source inspection remain useful evidence, but they are
not counted as runtime verification.

## Safety boundary

The dependency-free workflow remains the reference implementation. OpenHarness
logic stays behind `openharness_adapter.py`; paper-only enforcement remains
active and no live broker path is added.
