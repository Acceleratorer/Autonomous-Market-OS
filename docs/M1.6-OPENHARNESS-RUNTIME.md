# M1.6: Runtime-verified OpenHarness integration

**Date:** 2026-10-13

**Decision:** OpenHarness remains provisional. The real runtime passed the safe
no-network probe and the Market OS parity comparison, but promotion is blocked
until the runtime-specific failure, cancellation, and multi-agent scenarios are
exercised directly.

## Isolated execution

The verification environment was created outside this repository and installed
the OpenHarness package from the child repository's `pyproject.toml`. The probe
used a scripted in-process model client, so it made no provider request and did
not require credentials. The Market OS workflow and JSONL store stayed in the
fusion repository and remained the reference implementation.

Run the machine-readable check with:

```text
python -m market_os.orchestration.parity --root .market_os-parity-runtime --openharness-python C:\Temp\autonomous-market-os-openharness-venv\Scripts\python.exe
```

The command completed with `runtime_verified=true`, zero mismatches, and
`promotable=false`.

## Runtime-verified behavior

- OpenHarness session build, start, prompt handling, and clean close.
- Registered tool invocation through the actual query engine.
- Extra skill discovery and inclusion in the runtime prompt.
- Session snapshot persistence and reload by session ID.
- Two runtime turns invoking the same idempotent Market OS task and returning
  the same persisted result.
- Market OS result, event, artifact, citation, risk, paper-only, and contract
  checks matching the dependency-free reference path.
- Runtime event capture with child session IDs retained as provenance while
  Market OS run IDs remain the domain key.

## Source-based analysis

The OpenHarness source shows dedicated paths for stream events, session
snapshots, task cancellation, restart notices, skill loading, memory, and
in-process agent coordination. Those paths informed the adapter boundary, but
source inspection is not runtime evidence.

## Test-double behavior

The existing fixture runtime remains available and is still the default when no
isolated interpreter is supplied. It keeps the root workflow runnable without
OpenHarness dependencies.

## Unsupported or unverified behavior

- OpenHarness multi-agent coordination was not exercised by the no-network
  probe.
- OpenHarness-native failure propagation and cancellation were not exercised.
- Provider-backed model calls, external market data, document retrieval, and
  broker calls were not connected.
- Performance, deployment packaging, and production retention were not proven.

The Market OS reference path still has direct checks for failure, cooperative
cancellation, restart inspection, idempotency, artifact lineage, and live
execution rejection. That evidence does not promote the child runtime's own
equivalent behavior.

## Required translations

OpenHarness session and stream event names remain behind the adapter. The probe
records the child session ID, while translated Market OS events use the root
`run_id`. Task IDs and timestamps are adapter-owned; stable task fields are
compared exactly.

## Runtime failures, dependency, and security notes

- The first probe attempt failed because the isolated install had not completed;
  the environment was then installed successfully and rerun.
- The child package has a broad optional surface. Only its declared runtime
  dependencies were installed in the temporary environment; none were added to
  the fusion package.
- No credentials are read by the probe. The scripted client prevents network
  calls, and live Market OS execution remains rejected by `market-os.v1`.
- The adapter launches only the explicitly supplied interpreter and passes a
  temporary workspace plus the fusion source path through `PYTHONPATH`.

## Promotion gate

OpenHarness is not promoted. Promotion requires a second isolated probe that
records direct evidence for runtime failure normalization, cancellation,
restart after interruption, and multi-agent coordination, followed by a
deployment review. M2 must not connect real providers until that gate is
closed.
