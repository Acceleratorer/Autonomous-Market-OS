## Fixture and normalization

`market_os/tests/fixtures/vibe_trading/etf_ohlcv.json` contains six synthetic
daily rows each for SPY, QQQ, and IWM. It is labeled synthetic and not
historical market data. The adapter validates finite positive prices, OHLC
relationships, non-negative volume, unique ordered dates, required symbols,
UTC retrieval metadata, and a single venue/currency/adjustment basis.

Normalized bars carry `MarketBar` and `Provenance`; adapter metadata carries
the fixture content SHA-256 and license classification. The fixture is
synthetic internal data and is not presented as redistributable market history.

## Backtest rules

- Strategy: equal-weight long-only allocation across the requested symbols.
- Initial capital: `$10,000` in the acceptance run.
- Fees/slippage: Vibe-Trading global equity defaults with `slippage_us: 0.0`;
  the observed source metrics include its execution model and zero commission.
- Cash/shares: Vibe-Trading manages cash and fractional US-equity shares;
  orders emitted by Market OS remain integer paper orders in the root order
  contract.
- Alignment: daily bars, inclusive requested dates, local-loader rows only.
- Missing bars: fixture normalization rejects missing requested symbols or
  insufficient observations; no fill-forward or network fallback is applied.
- Fingerprint: SHA-256 over fixture content, symbols, date range, initial cash,
  strategy identifier, and Vibe-Trading source commit.

Independent reference arithmetic for the equal-weight close-to-close result is
`$10,000 * mean(104.0/100.5, 204.5/200.5, 154.0/150.5) = $10,260.10`.
The actual Vibe-Trading result is `$10,260.10` (`2.601%`). The adapter maps its
equity curve into the root `BacktestResult` and removes temporary child-run
files after completion; Market OS persists the normalized result and lineage
artifact.

## Root workflow

The CLI accepts `research ... --provider vibe-trading`; the API accepts
`provider` and `backtest_provider` in `POST /v1/tasks`. The default remains the
existing fixture provider. An unavailable Vibe-Trading adapter returns an
actionable error and never silently changes engines. Events include provider,
fixture, source reference, and content fingerprint metadata. Evidence citations,
backtest, order-plan, risk-decision, restart inspection, idempotency, and
paper-only enforcement remain root-owned.

The adapter passes cancellation to the child boundary and supports a positive
provider deadline. Deadline failure is actionable; cancellation terminalizes
the Market OS run as cancelled.
