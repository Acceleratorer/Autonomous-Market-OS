# B4.17 Local Retention and Archive Contract

**Status:** Implemented and verified locally on 2026-10-28 for the synthetic, paper-only portfolio store.

## Policy

- Retain the append-only ledger indefinitely under the local portfolio store.
- `backup_portfolio()` is an opt-in, local, immutable copy operation. It does not delete, truncate, rewrite, or archive-delete source history.
- `preflight_portfolio()` remains read-only and reports the current recoverable schema. It does not invent a target schema or transform history.
- No retention deletion, pruning, remote archive, or in-place migration is enabled by B4.17.

## Integrity boundary

- A portfolio with a checkpoint but no ledger fails closed as an incomplete store. Backup and migration preflight must reject it through broker recovery.
- A missing ledger and checkpoint is indistinguishable from a newly initialized zero-event portfolio under the existing format; detecting that state would require a new durable marker and contract.
- Validated backups preserve source bytes, ledger fingerprints, snapshots, reservations, audit outcomes, and replay equivalence.
- Future archive/delete work requires a new versioned contract that defines eligibility, backup precondition, immutable archive identity, restore verification, operator authorization, and recovery evidence before any deletion mutation.

## Boundary

The implementation remains local, synthetic, paper-only, and Python-only. CLI and HTTP mutation routes, providers, credentials, network access, live venues, and production infrastructure remain out of scope.
