# B4.12 Migration Preflight

**Status:** Implemented locally on 2026-10-28 as a read-only, synthetic, paper-only compatibility slice.

## Scope

- Verify that a portfolio can be recovered under the supported B4 schema.
- Report whether the current store is already at the supported broker schema and preserve the actual genesis schema identity for isolated or shared portfolios.
- Fail closed when schema identity or recovery validation is unsupported.
- Preserve immutable ledger history; the preflight never rewrites, upgrades, or deletes files.

The CLI entry point is `market-os b4-paper migration-check`. The Python seam is `preflight_portfolio()` in `market_os.portfolio_migration`.

## Boundary

B4.12 does not invent a v2 schema or transform old records. A future migration tool must define a versioned target schema, explicit field transforms, source and destination fingerprints, backup precondition, and replay-equivalence evidence before it can mutate a new store. Retention/archive operations and shared/mutation surfaces remain separate gates.
