# U5.3 Deployment, Access, and Observability Contract

**Status:** Implemented locally on 2026-10-28.
**Scope:** Static artifact handoff and loopback service diagnostics.

## Static handoff

`python scripts/build_web_artifact.py --output <directory> --manifest <path>`
produces the exact three-file static artifact plus a versioned JSON manifest.
The manifest records each file's size and SHA-256 hash, a deterministic
artifact fingerprint, and the synthetic/paper/read-only boundary. The manifest
contains no portfolio state, credentials, provider data, or deployment secret.
CI uploads the manifest as a sidecar next to the static directory; it is not
placed inside the three-file web directory.

## Local observability

Every local gateway response carries an `X-Request-ID` value. The same value is
written to the structured JSONL request audit record with method, URL path,
status, run ID, and error type. Query values remain excluded from logs. The ID
is diagnostic correlation only; it is not an authenticated identity.

## Access boundary

The current service remains loopback-only and rejects untrusted `Host` headers.
The static artifact remains disconnected from the service. No public listener,
authentication provider, tenant sharing, mutation route, provider, credential,
or live venue is enabled by this contract.

## Promotion gate

Before any connected or public deployment, a separate versioned contract must
define authenticated identity, authorization, tenant storage isolation, secret
handling, rate limits, production log retention, alerting, backup/restore,
rollback, and an explicit paper-only mutation policy. U5.3 does not satisfy
those requirements.
