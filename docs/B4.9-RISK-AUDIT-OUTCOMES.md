# B4.9 Risk and Audit Outcomes

**Status:** Implemented locally on 2026-10-27 as a synthetic, paper-only hardening slice. Extended by B4.14 on 2026-10-28 for all local Python mutation methods.

**Purpose:** Make order risk and approval failures deterministic, auditable, and idempotent at the paper command seam.

## Scope

- Record rejected order commands as `order.rejected` ledger events.
- Return stable `reason_code` values for risk, approval, precision, timing, and duplicate-order failures.
- Scope submit idempotency across both accepted and rejected outcomes.
- Return the original rejected outcome on an identical retry without adding another ledger event or changing balances, orders, or fills.
- Record rejected cancel and approval-revocation commands as typed ledger events with the same replay behavior.
- Record idempotency conflicts as audit events without assigning the attempted probe a command idempotency identity.
- Expose rejected command outcomes through the existing read-only `risk` and `approvals` inspection resources.

## Public seam and evidence

The public seams are `B41Broker.submit_order()`, `B41Broker.cancel_order()`, `B41Broker.revoke_approval()`, and `B41Broker.inspect()`. Regression coverage is in [test_portfolio_broker.py](../market_os/tests/test_portfolio_broker.py) and [test_portfolio_mutation.py](../market_os/tests/test_portfolio_mutation.py), including risk/approval rejection, deterministic retry, recovery equivalence, idempotency conflict audit, and no-mutation assertions.

## Boundaries

B4.9/B4.14 do not add a mutation API route, change risk limits, add partial fills or expiry, share portfolios, call providers, use live data, trade, deploy, commit, or push. The B4.1 contract remains the source of truth for owner-approved policy values and broader approval semantics.
