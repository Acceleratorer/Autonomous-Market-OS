# B4.9 Risk and Audit Outcomes

**Status:** Implemented locally on 2026-10-27 as a synthetic, paper-only hardening slice.

**Purpose:** Make order risk and approval failures deterministic, auditable, and idempotent at the paper command seam.

## Scope

- Record rejected order commands as `order.rejected` ledger events.
- Return stable `reason_code` values for risk, approval, precision, timing, and duplicate-order failures.
- Scope submit idempotency across both accepted and rejected outcomes.
- Return the original rejected outcome on an identical retry without adding another ledger event or changing balances, orders, or fills.
- Expose rejected order outcomes through the existing read-only `risk` inspection resource.

## Public seam and evidence

The public seams are `B41Broker.submit_order()` and `B41Broker.inspect("risk")`. Regression coverage is in [test_b41_broker.py](../market_os/tests/test_b41_broker.py), including inventory rejection, approval rejection, deterministic retry, and no-mutation assertions.

## Boundaries

B4.9 does not add a mutation API route, change risk limits, add partial fills or expiry, share portfolios, call providers, use live data, trade, deploy, commit, or push. The B4.1 contract remains the source of truth for owner-approved policy values and broader approval semantics.
