# M1.8: OpenHarness recovery blocker closure

**Date:** 2026-10-14
**Decision:** OpenHarness remains **Provisional**.

## Scope

M1.8 keeps the dependency-free `MarketWorkflow` and `RunStore` as the
reference implementation and strengthens the adapter boundary around failure,
cancellation, restart inspection, and multi-agent result handling. The isolated
OpenHarness 0.1.9 probe still uses scripted local clients. No credentials,
external market or document providers, brokers, or live execution are used.

## Recovery behavior implemented

- Storage errors are normalized with the operation name (`event.append`,
  `artifact.write`, `run.finalize`, and similar) and a terminal `failed` run is
  written when storage recovers.
- Recovery records are append-only in `recovery.jsonl` and include task/run
  identity, terminal status, retry policy, traceback, and partial artifact
  state. Artifact files are retained even when their index write fails.
- Cancellation is checked before work, after artifact writes, and before
  finalization. A cancellation produces a durable `cancelled` run and event;
  repeated cancellation is idempotent.
- `recover_inflight_runs()` converts abandoned `running` records after process
  restart into inspectable `failed` records with
  `restart_interrupted:resume_unsupported`. Provider/backtest resume is not
  claimed.
- Artifact indexing is idempotent by content-derived artifact ID.
- `market-os.multi-agent.v1` defines ordered agent results, fingerprints,
  exact duplicate suppression, same-agent conflict records, partial status,
  individual errors, artifact and evidence references, and final aggregate
  status.

## Evidence

The machine-readable report is
[`docs/evidence/m1.8-openharness-recovery.json`](evidence/m1.8-openharness-recovery.json).
It distinguishes direct runtime evidence, adapter-boundary evidence, and
unsupported runtime behavior.

Direct OpenHarness 0.1.9 evidence confirms provider/tool/contract/session
failure observation, cancellation before and during provider/tool work,
session persistence failure, basic two-agent identity and shared run
coordination, timeout observation, idempotent replay, artifact lineage, event
trace completeness, terminal status, and paper-only enforcement.

The root adapter boundary now directly verifies terminal persistence recovery,
partial artifact inspection, restart cleanup, and aggregation semantics.

## Remaining blockers

OpenHarness is not promoted because the child runtime still does not provide
runtime-native evidence for:

1. cooperative cancellation during synchronous artifact persistence;
2. resume of cancelled in-flight work after restart;
3. durable mid-turn checkpointing while provider work is running;
4. partial teammate failure propagation from the in-process loop;
5. runtime-native duplicate teammate result handling;
6. deployment and dependency review in a service/container environment.

The root-owned adapter contract makes these gaps explicit and safe, but it does
not convert adapter evidence into runtime evidence.

## Safety boundary

Paper-only enforcement remains active. M2 stays blocked from real providers and
live trading until the promotion decision changes.
