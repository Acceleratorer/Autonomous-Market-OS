# M1.10: Bounded deployment wrapper and final blocker evidence

**Date:** 2026-10-14
**Wrapper decision:** Accepted for local paper-only deployment.
**OpenHarness decision:** Provisional.

## Wrapper

`market_os/deployment/wrapper.py` is a stdlib-only process owner for the local
service. It validates absolute paths, keeps state and logs under one explicit
runtime root, permits loopback hosts only, forces paper-only mode, applies
startup, readiness-request, and shutdown timeouts, handles graceful and forced termination,
normalizes exit status, and writes structured JSONL lifecycle logs.

The wrapper fails closed when required paths are absent, paths escape the
runtime root, a non-loopback host is requested, live mode is selected, or host
CPU/memory limits are requested without an external supervisor. The last case
is an explicit rejection of host-level enforcement, not a silent claim that
Python can bound its own process.

It does not create credentials, enable live trading, connect to external
providers, or replace the dependency-free `MarketWorkflow` and `RunStore`
reference path. Production CPU/memory quotas, service-account permissions,
provider request deadlines, and service audit sinks require the host supervisor
or deployment platform.

## Evidence

The machine-readable report is
[`docs/evidence/m1.10-openharness-blockers.json`](evidence/m1.10-openharness-blockers.json).
It records 48 named scenarios and separates direct runtime behavior,
adapter-boundary behavior, unsupported native capabilities, and deployment
observations.

## Promotion

Direct OpenHarness evidence still shows no runtime-native cancellation during
synchronous persistence, no in-flight checkpoint/resume, swallowed teammate
failure and cancellation outcomes, and no native duplicate-result handling.
Restart cases are recover-and-mark-failed or inspect-only at the adapter
boundary; safe replay and deterministic duplicate/conflict handling remain
root-owned adapter behavior.

The local service lifecycle passes through the wrapper. The service itself does
not prove host CPU/memory quotas, service request/provider timeouts beyond the
wrapper's readiness check, service request/audit logs, or production identity
permissions.

**Provisional.** M2 remains blocked from real providers, credentials, brokers,
and live execution.

M1.11 must either add a supported external supervisor for those controls or
explicitly reject the current deployment shape, and must obtain native
checkpoint/resume, teammate propagation, and duplicate-handling evidence.
