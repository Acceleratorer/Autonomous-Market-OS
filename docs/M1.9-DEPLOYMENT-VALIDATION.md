# M1.9: Deployment validation and remaining blockers

**Date:** 2026-10-14
**Decision:** OpenHarness remains **Provisional**.

## Reproduction

The fusion service runs with Python 3.11 or newer and no package dependency.
The isolated OpenHarness probe uses Python 3.12.0 and `openharness-ai:0.1.9`
from `C:\Temp\autonomous-market-os-openharness-venv`. The child repository is
loaded as an external source tree; it is not copied into this repository.

```powershell
python -m pytest -q
python -m compileall -q market_os
python -m market_os.deployment_probe `
  --output docs/evidence/m1.9-deployment-validation.json `
  --openharness-python C:\Temp\autonomous-market-os-openharness-venv\Scripts\python.exe
```

The deployment probe launches `market_os.cli serve` in a temporary state root,
checks `/healthz` and `/readyz`, submits a paper-only task, inspects persisted
events and artifacts, verifies startup recovery, clean shutdown, clean restart,
forced shutdown, filesystem isolation, and the no-secret request boundary. It
uses deterministic local providers and no external network, credentials,
market data, document provider, broker, or live execution.

## Evidence classes

- `deployment-verified`: observed from a launched local service process.
- `runtime-verified`: observed from the isolated OpenHarness 0.1.9 child runtime.
- `runtime-verified-adapter-boundary`: observed in the Market OS adapter while the child runtime is present.
- `unsupported`: the probe exercised the boundary and found the capability absent.
- `source-based`: documented deployment assumption, not runtime proof.

The complete machine-readable report is
[`docs/evidence/m1.9-deployment-validation.json`](evidence/m1.9-deployment-validation.json).

## Results

Service lifecycle, health/readiness, paper task API, event and artifact
inspection, startup recovery, clean restart, forced termination, state-root
isolation, and the no-secret fixture boundary passed. `pip check` reports no
broken requirements in the isolated OpenHarness environment.

The deployment gate remains open because process resource limits, request and
shutdown timeouts, and structured operational logging are not configured.
The temporary probe also cannot prove production service-account filesystem
permissions.
Upgrade and rollback remain source-based assumptions because no image registry
or migration runner is exercised in this milestone.

The isolated OpenHarness probe passed 19 runtime cases and 3 adapter-boundary
cases. Runtime blockers remain for synchronous artifact persistence
cancellation, in-flight checkpoint/resume, partial teammate failure
propagation, and native duplicate teammate handling. The adapter keeps these
cases safe at the Market OS boundary with durable terminalization, inspection,
restart cleanup, and `market-os.multi-agent.v1` aggregation.

## Promotion decision

**Provisional.** M2 remains blocked from real providers, document services,
brokers, credentials, and live execution.

## Next milestone

M1.10 must add or explicitly reject a bounded deployment wrapper with resource
limits, request and shutdown timeouts, and structured logs, then rerun the
promotion gate. Direct OpenHarness evidence for checkpoint/resume, partial
failure propagation, and duplicates is still required.
