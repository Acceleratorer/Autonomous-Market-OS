# B4.13 Local Concurrency Contract

**Status:** Implemented and verified locally on 2026-10-28 for the approved synthetic, paper-only boundary.

## Contract

- A portfolio is isolated by strategy, instrument, and fixture lineage.
- One writer may mutate a portfolio at a time. Mutating broker methods take the local process lock and the portfolio writer lock.
- Every committed mutation advances the append-only ledger sequence and hash chain.
- A broker instance records the ledger head it loaded. If another writer commits first, the stale instance fails closed with `stale portfolio snapshot; reload before writing`.
- Reloading through `B41Broker.open()` recovers the committed state and permits a subsequent write.
- Same idempotency key and payload replays the recorded result; conflicting payloads are rejected.

## Deliberate boundary

B4.13 does not add shared portfolio membership, cross-strategy reservations, fair scheduling, distributed ownership, network locks, or mutation API routes. Those remain separate U4 decisions.

## Evidence

Regression coverage is in `market_os/tests/test_portfolio_concurrency.py`. It proves stale writers are rejected until reload and that separate portfolio identities maintain independent ledger heads and lock files.
