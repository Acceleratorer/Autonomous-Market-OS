# U5.12 One-Pass Audit Page Freshness

**Status:** Implemented and measured locally on 2026-10-29.  
**Scope:** Remove a redundant full-ledger read from local risk, approval, and ledger page inspection while retaining cold recovery and stale-state checks.

## Contract

Cold broker recovery continues to replay and validate the complete append-only
ledger. During a risk or audit page request, the existing bounded selection
scan also records the final event fingerprint. The broker compares that value
with the head recovered earlier while holding the portfolio process lock. A
changed head raises `BrokerStale`; catalog routes return HTTP 409, and the
existing B4 resource routes retain their conflict response.

This replaces the previous second full-file `read_text().splitlines()` head
read. It does not skip ledger replay, change cursor semantics, trust a cache or
filesystem timestamp, or change the stored schema.

## Verification

- Red/green regression tests prove that risk and ledger page inspection do
  not call the separate `_ledger_head()` reader and still reject a ledger that
  changes after recovery.
- Focused broker, shared-portfolio, operator, U5 acceptance, and
  application-surface tests: 53 passed.
- Synthetic measurement used 100 ledger records (3.48 MB), three cold opens,
  and five page reads per resource. Local medians:

  | Operation | Before | After |
  |---|---:|---:|
  | Cold broker recovery | 408.4 ms | 402.6 ms |
  | Ledger page | 28.8 ms | 20.6 ms |
  | Risk page | 26.4 ms | 20.3 ms |

  This is a local diagnostic sample, not a CI performance threshold. Catalog
  timings varied between runs; catalog code did not change.
- Python compile check, evidence JSON parsing, and `git diff --check` passed.

## Remaining limits

Catalog enumeration still sorts every directory and fully recovers each
candidate. Cold recovery still validates every ledger record. Risk, approval,
and ledger pages still scan the ledger once to compute counts and select rows.
Any future cache or durable index needs a separate invalidation, rebuild, and
integrity contract. Connected access remains gated by U5.5; B4 deletion and
schema transformation remain separate decisions.
