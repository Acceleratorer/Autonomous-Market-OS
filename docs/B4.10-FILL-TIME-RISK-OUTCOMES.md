# B4.10 Fill-Time Risk Outcomes

**Status:** Implemented locally on 2026-10-27 as a synthetic, paper-only hardening slice.

**Purpose:** Make market-order risk failures terminal and auditable when the fill price is only known at market-event processing time.

## Scope

- Transition an affected order to terminal `risk_rejected` when computed fill notional is outside the approved range.
- Record stable `risk.minimum_notional` or `risk.max_order_notional` outcomes in the committed `market.processed` result.
- Advance the market-event cursor and preserve deterministic recovery.

## Public seam and evidence

The public seam is `B41Broker.process_market_event()`. Regression coverage is in [test_portfolio_broker.py](../market_os/tests/test_portfolio_broker.py), including event progress, terminal order state, risk inspection, and recovery equivalence.

## Boundaries

B4.10 does not add partial fills, expiry, shared portfolios, distributed concurrency, mutation API routes, backup/retention/migration tooling, provider access, live data, trading, deployment, commit, or push.
