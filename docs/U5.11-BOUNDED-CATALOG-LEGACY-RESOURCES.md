# U5.11 Bounded Portfolio Catalog and Legacy Resources

**Status:** Implemented and verified locally on 2026-10-29.  
**Scope:** Bound the local portfolio directory and every B4 HTTP collection response while retaining cursor-based inspection.

## Contract

`GET /v1/b4/portfolios` and the `/operator/` HTML registry return a sorted
portfolio page. `limit` defaults to 25 and accepts 1–100; the exclusive
`after_portfolio_id` cursor must identify a recoverable catalog entry. An
unreadable portfolio candidate is skipped and counted in `page.skipped_count`;
both local registries announce skipped candidates to the operator. The response
contains at most `limit` portfolio summaries and a `page` object with
`has_more` and `next_after_portfolio_id`. Catalog rows expose `member_count`
instead of embedding every strategy ID. The Next.js registry validates this
shape and renders server-side first/next-page links; the compatibility HTML
registry uses the same bound and cursor.
If a portfolio changes after recovery but before its catalog summary is read,
the API returns HTTP 409 so the caller can retry; it does not label a concurrent
update as corrupt data.

All HTTP B4 collection resources now default to 25 rows and cap each page at
100. Cursors are exclusive and resource-specific:

| Resource | Limit | Cursor |
|---|---|---|
| `genesis` members | `member_limit` | `member_after_strategy_id` |
| `reservations` | `reservation_limit` | `reservation_before_order_id` |
| `orders` | `order_limit` | `order_before_id` |
| `fills` | `fill_limit` | `fill_before_id` |
| `risk` records | `risk_limit` | `risk_before_sequence` |
| `approvals` records | `approval_limit` | `approval_before_sequence` |
| `ledger` events | `ledger_limit` | `ledger_before_sequence` |

The legacy v1 aggregate also pages its member and reservation arrays, in
addition to orders and risk outcomes. Summary resources use the compact
market-event count rather than returning the event ID cursor. Risk, approval,
and ledger pages keep the complete selected records in a bounded window.
Unknown or repeated parameters, invalid limits, and stale cursors return HTTP
400. The full `snapshot` export is rejected over HTTP because it combines
multiple complete histories; broker-internal snapshot inspection remains
available to local Python callers.

The response change is local-only. The API remains loopback-only, synthetic,
paper-only, GET-only, and read-only. It adds no identity, deployment, mutation,
credential, provider, real-data, or venue path.

## Remaining local limit

Page output is bounded, but directory enumeration still sorts all portfolio
directory names and opening each displayed portfolio still performs validated
ledger recovery. U5.12 removed a redundant ledger-head read while preserving
the full cold recovery and one page scan; a future index or cache still needs
an explicit invalidation and integrity contract.
The U5.5 connected-web gate and the B4 deletion/schema-transformation gates
remain separate.
