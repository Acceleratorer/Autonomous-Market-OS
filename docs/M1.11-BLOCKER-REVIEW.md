# M1.11: OpenHarness blocker review

**Date:** 2026-10-14
**Promotion status:** Provisional
**M2 readiness:** Deferred

## Decision

The dependency-free Market OS workflow and adapter safely close several
failure and recovery behaviors at the boundary. OpenHarness remains
provisional because native persistence cancellation, checkpoint/resume,
teammate failure and cancellation propagation, duplicate-result handling,
process resource quotas, provider/workflow execution deadlines, and service
identity permissions are not directly verified.

The service boundary now has two tested controls: a bounded HTTP socket read
timeout and structured JSONL request outcome logs. The HTTP timeout does not
bound synchronous provider or backtest execution, so that distinction remains
explicit in the evidence.

## Classification summary

| Area | Classification | Promotion impact |
| --- | --- | --- |
| Persistence failure terminalization | Closed | No blocker at the Market OS boundary |
| Cancellation checkpoints and partial artifacts | Mitigated at adapter boundary | Native persistence cancellation remains a blocker |
| Restart cleanup | Mitigated at adapter boundary | Native checkpoint/resume remains a blocker |
| Partial teammate aggregation | Mitigated at adapter boundary | Native propagation remains a blocker |
| Duplicate fingerprints and conflicts | Mitigated at adapter boundary | Native duplicate handling remains a blocker |
| Structured service logging | Closed for the local shape | Production sink and retention remain deployment work |
| HTTP request-body timeout | Closed | Provider/workflow execution deadline remains separate |
| Provider/workflow execution timeout | Promotion-blocking | Requires worker/provider deadline evidence |
| CPU and memory quotas | Unsupported | Requires an external supervisor |
| Service identity and filesystem ACLs | Unsupported | Required for shared or production deployment |
| Native persistence cancellation | Requires OpenHarness change | Promotion-blocking |
| Native checkpoint/resume | Requires OpenHarness change | Promotion-blocking |
| Native teammate failure/cancellation | Requires OpenHarness change | Promotion-blocking |
| Native duplicate results | Requires OpenHarness change | Promotion-blocking |

## Adapter boundary

`MarketWorkflow` records terminal recovery metadata when event, artifact, or
terminal state writes fail. Cancellation checkpoints occur around provider,
artifact, event, and finalization boundaries. Restart cleanup marks abandoned
runs failed with `restart_interrupted:resume_unsupported`. The aggregation
contract preserves teammate identity, ordering, individual failures, partial
status, artifact lineage, exact duplicates, and same-agent conflicts.

These guarantees are Market OS behavior. They are not evidence that
OpenHarness provides the same guarantees natively.

## Deployment boundary

The local wrapper remains accepted for loopback, paper-only operation. It
confines state and logs under an explicit runtime root, owns graceful and
forced shutdown, and records lifecycle JSONL. The service now records request
method, path, status, run identity, and error type in JSONL, and returns HTTP
408 for a stalled request body.

The wrapper intentionally fails closed when CPU or memory limits are requested
without an external supervisor. It also does not claim to create service
identities, filesystem ACLs, or provider execution deadlines.

## M2 readiness

M2 implementation is deferred. Planning may proceed for licensed market-data,
document/news, Vibe-Trading research/backtest, and LightRAG or RAG-Anything
evidence adapters. No real provider, credential, broker, or live execution
path is enabled by M1.11.

The next milestone is **M1.12: choose and verify the external supervisor and
OpenHarness-native closure path, or formally reject this deployment/runtime
shape**.
