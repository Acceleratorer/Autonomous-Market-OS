# B4.8 Snapshot Scalar Validation

**Status:** Implemented locally on 2026-10-27 as a synthetic, paper-only hardening slice.

**Purpose:** Validate persisted snapshot scalar and cursor shapes before recovery mutates the in-memory broker state.

## Scope

- Require snapshot numeric fields to be finite numeric values.
- Require `last_event_time_ms` to be an integer when present.
- Require `equity_history` to be a list of two-item timestamp/value points.
- Require revoked approval IDs and event cursors to be lists of strings.
- Keep malformed snapshot failures behind the existing `BrokerRejected("ledger resulting snapshot is malformed")` recovery boundary.

## Public seam and evidence

The public seam is `B41Broker.open()` / `B41Broker.recover()`. Regression coverage is in [test_portfolio_broker.py](../market_os/tests/test_portfolio_broker.py), covering invalid event time, cursor shape, and equity-history shape with self-consistent persisted fingerprints.

## Boundaries

B4.8 does not repair or skip malformed snapshots, change the ledger format, add a new persistence backend, add partial fills or expiry, expose mutation API routes, share portfolios, call providers, use live data, trade, deploy, commit, or push. The B4.1 contract remains the source of truth for broader replay and schema migration policy.
