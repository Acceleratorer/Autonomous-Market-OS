# ADR-0053: U6.2 native platform selection\n\n**Date:** 2026-11-03\n**Status:** Accepted; implementation and U6.4-A unsigned artifact locally verified; U6.4-B signing and rollback remain open\n**Scope:** Local, read-only desktop shell over the existing U6.1 Next.js surface\n\n## Context\n\nU6.1 verified gateway status, overview, and BTC dataset catalog in the\nserver-rendered Next.js shell. The shell is local, synthetic, paper-only, and\nGET-only. The next decision must choose a native container without creating a\nsecond API client, persistence layer, or unbounded filesystem bridge.\n\nPython `market_os` remains authoritative for accounting, persistence, recovery,\nresearch inspection, and paper state. The Next.js shell remains the reference\nrenderer and must consume the same versioned envelopes as the Python API and\nCLI. The native layer may supervise local processes, but it must not read the\nportfolio root or implement domain logic.\n\n## Decision\n\nSelect **Electron** for the first U6 desktop container. Target Windows x64 and\nLinux x64 first; mobile and macOS remain deferred. Keep the existing Next.js\noperator as the renderer and keep the Python gateway as the domain and storage\nauthority.\n\nElectron is the smallest implementation-risk choice for this repository: the\ncurrent shell already depends on Node.js and uses server-rendered Next.js, so a\ndesktop main process can own the local Next.js and Python gateway lifecycle\nwithout introducing a Rust build toolchain or a second renderer. Electron's\nlarger bundled runtime and privileged main/preload boundary are accepted only\nwith strict sandbox, context-isolation, IPC, navigation, and loopback gates.\n\nPrimary references: [Electron process model](https://www.electronjs.org/docs/latest/tutorial/process-model),\n[Electron security](https://www.electronjs.org/docs/latest/tutorial/security),\n[Electron sandbox](https://www.electronjs.org/docs/latest/tutorial/sandbox),\n[Electron updater](https://www.electronjs.org/docs/latest/api/auto-updater/),\n[Tauri architecture](https://v2.tauri.app/concept/architecture/),\nand [Tauri updater](https://v2.tauri.app/plugin/updater/).\n\n## U6.3 local slice and U6.4 release contract\n\nThe U6.3 local slice must satisfy the lifecycle, transport, security, failure,\nand parity gates below. Release packaging is intentionally a separate U6.4\ngate.\n\n1. **Renderer parity:** load the existing Next.js shell and prove gateway\n   status, overview, and BTC dataset catalog parity for envelopes, bounds,\n   cursors, ordering, empty stores, invalid input, and exact values.\n2. **Local lifecycle:** start and stop the Python gateway and Next.js server as\n   owned child processes on loopback only; use a bounded readiness handshake,\n   terminate descendants on exit, and fail closed when either process is\n   missing or unhealthy.\n3. **Transport:** allow only `127.0.0.1` HTTP to configured local ports; never\n   load a remote URL, expose a public listener, or forward Tailscale identity.\n4. **Electron security:** enable sandbox and context isolation, disable Node\n   integration in renderers, validate IPC senders, restrict navigation and\n   window creation, and expose no filesystem or portfolio commands by default.\n5. **U6.4 packaging:** U6.4-A builds reproducible unsigned Windows and Linux\n   artifacts with exact hashes; U6.4-B adds signed metadata and explicit update\n   rollback. No updater endpoint or signing key belongs in the repository. Linux updates remain a separate\n   package-manager/manual gate because Electron's built-in updater is not a\n   Linux updater.\n6. **Failure behavior:** show the existing unavailable state, stop owned\n   processes, preserve local state, and leave no mutation or partial update\n   path after failed startup or update.\n7. **Responsive/accessibility parity:** retain U6.1 gates at 320, 375, 768,\n   1024, and 1440 pixels, 44px targets, keyboard focus, labelled table\n   scrolling, and reduced-motion behavior.\n\n## Alternatives\n\n| Option | Decision | Reason |\n|---|---|---|\n| Electron | **Selected** | Reuses the existing Node.js/Next.js runtime and keeps the first native lifecycle slice small. |\n| Tauri 2.x | Fallback | Stronger native capability boundary and smaller footprint, but requires Rust, sidecar integration, and host WebView prerequisites before this SSR shell can be proven. |\n| React Native / Flutter | Deferred | Requires a second renderer and parity adapter before the existing Next.js shell is stable as a native reference. |\n| No native container | Rejected for U6.2 | Leaves the requested platform decision unresolved after U6.1. |\n\n## U6.3 result\n\nThe local Electron slice is verified in `apps/desktop/electron`. Its main\nprocess starts the existing Python gateway and server-rendered Next.js operator\nwith separate working directories, waits for bounded loopback readiness, and\ncleans up owned descendants. A real headless smoke returned 200 from both\nreadiness endpoints and `/overview`, then closed both custom ports after\ngraceful shutdown.\n\nThe renderer uses sandbox, context isolation, disabled Node integration, web\nsecurity, denied window creation, and loopback-only navigation. The preload\nexposes immutable read-only metadata and no domain, filesystem, or mutation\ncommands. U6.4-A now verifies an unsigned artifact with a source-bundled Python\nsidecar and release manifest; signed metadata, sidecar distribution, and update\nrollback remain U6.4-B.\n\n## Consequences\n\n- U6.2 added the platform decision and acceptance gates. U6.3 adds only an\n  isolated local Electron developer shell and its focused evidence.\n- The existing Next.js shell remains the renderer and Python remains the\n  domain/storage authority; no packaged native release exists yet.\n- Electron's renderer must remain unprivileged; the main process is the only\n  place allowed to supervise local services.\n- U5.5 owner-VM promotion and rollback remain a separate pending gate.\n\n## Explicit non-goals\n\nNo mobile shell, provider access, credentials, connected identity, mutation\nroute, live trading, public listener, portfolio filesystem API, or native\nplatform deployment is authorized by this ADR.\n\n
