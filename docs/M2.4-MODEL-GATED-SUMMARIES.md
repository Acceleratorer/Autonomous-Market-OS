# M2.4: Explicit model-gated research summaries

Status: implemented and verified offline with the deterministic test provider.
No hosted model or external model provider is integrated.

## Behavior before M2.4

M2.3 emits `market-os.research.v1` exact-quote claims, claim supports,
citations, unsupported claims, deterministic evidence coverage, and a stable
synthesis fingerprint. The legacy `market-os.v1` result remains unchanged.
The M2.3 synthesis remains the default and trusted research result.

## Additive contract

`market_os.model_summary` defines the separately versioned
`market-os.model-summary.v1` contracts:

- `SummaryRequest`: objective, M2.3 synthesis fingerprint, normalized input and
  prompt fingerprints/version, and claim/passage IDs.
- `ModelProviderIdentity` and `ModelUsage`: provider/model/version and optional
  usage/cost metadata.
- `ModelFailure`: explicit provider error/timeout classification and error type
  for deterministic fallback records.
- `GeneratedStatement`: text, stable statement ID, classification, resolved
  citation/support/document IDs, exact evidence quotes, and optional
  confidence.
- `SummaryValidation`: validated/rejected status, errors, counts by
  classification, resolved citation IDs, and supported-statement coverage.
- `GateDecision`: approved, rejected, or provider-failure fallback, with reason
  and deterministic-fallback state.
- `ModelGatedSummary`: request, identity, statements, validation, gate,
  fingerprints, and lineage to the persisted M2.3 artifact.

This contract is additive; `market-os.v1` and `market-os.research.v1` readers
remain supported.

## Gate and grounding rules

- No summary provider is selected by default. Deterministic M2.3 synthesis is
  always performed first and is never replaced in storage.
- `--summary-provider deterministic-test` or
  `summary_provider: "deterministic-test"` explicitly selects a local
  deterministic test double together with the explicit `lightrag` cited
  retrieval provider and a selected backtest provider. Any other provider name
  or a summary selection without cited retrieval fails selection. This is not a
  real model integration.
- A supported statement must resolve to exactly one base claim through its
  support and citation IDs; its document IDs and citations must match those
  persisted supports; its statement text must equal an exact support quote;
  and every evidence quote must equal stored passage text.
- A summary is rendered only from its classified statements. Inference and
  unsupported statements receive visible `Inference:` or `Unsupported
  (ungrounded):` labels. The generated free-form summary string must exactly
  equal this classified rendering; it cannot smuggle in uncategorized prose.
- `rejected` model output remains inspectable with validation errors but its
  summary text is not published. A provider exception/timeout yields `fallback`
  with no model text and the M2.3 synthesis fingerprint preserved.
- A provider-declared inference is explicitly labeled and counted separately;
  the gate validates its citations and provenance when supplied, but cannot
  establish semantic entailment. It is not counted as evidence-supported.
- Model summaries do not change order plans, risk decisions, or execution mode.

## Coverage and fingerprints

Model-summary evidence coverage is supported statements divided by all
generated statements (supported + inference + unsupported + rejected). An
empty output has zero coverage and is rejected by the output contract. It is a
summary-output metric, distinct from the M2.3 synthesis coverage.

`input_fingerprint` hashes canonical serialized M2.3 synthesis content.
`prompt_fingerprint` hashes objective, prompt version, and input fingerprint.
`output_fingerprint` hashes the published summary text, statements, usage, and
validation (including failure metadata). `summary_fingerprint` hashes request,
provider identity, output fingerprint, validation, and gate decision. The
deterministic fallback fingerprint must equal the M2.3 synthesis fingerprint.
Persisted inspection recomputes structural fingerprints and verifies lineage
against the cited artifact.

## Selection and inspection

Examples:

```text
market-os research "Summarize cited SPY fixture research" --symbols SPY --provider lightrag --backtest-provider vibe-trading --summary-provider deterministic-test
market-os inspect <run-id> --resource model-summary
market-os inspect <run-id> --resource inferences
```

Task API selection adds `summary_provider` to `POST /v1/tasks`:

```json
{
  "objective": "Summarize cited SPY fixture research",
  "symbols": ["SPY"],
  "start": "2026-01-02",
  "end": "2026-01-09",
  "provider": "lightrag",
  "backtest_provider": "vibe-trading",
  "summary_provider": "deterministic-test"
}
```

Read-only inspection endpoints:

```text
GET /v1/runs/<run-id>/research/model-summary
GET /v1/runs/<run-id>/research/inferences
```

Inspection reads persisted artifacts only. It invokes no retrieval, model, or
backtest provider and performs no trading-state writes. It verifies artifact
SHA-256, model-summary schema/fingerprints, M2.3 synthesis fingerprint, and
model-summary-to-cited-research lineage. Unknown runs/items return not found;
missing/corrupt artifacts or incomplete lineage return an integrity error.

## Security, privacy, and limitations

The only selectable model adapter is local and deterministic. No credentials,
network calls, prompt service, external provider, or cost-bearing request is
made. Summary artifacts contain the generated statements, evidence IDs and
quotes, provider identity, fingerprints, and usage metadata. They intentionally
omit private runtime configuration and filesystem paths from model identity.
The existing artifact store retains its local paths for owner inspection.

Exact-quote validation is deliberately conservative: richer paraphrases are
rejected even if a human might consider them accurate. Conversely, citation
validity alone cannot prove a labeled inference is semantically sound. A real
model provider, robust prompt-injection controls, asynchronous provider timeout
and cancellation protocol, and semantic entailment verification are not
implemented. Any future provider must remain opt-in and pass the same persisted
evidence gate without gaining authority over paper-only or risk policy.
