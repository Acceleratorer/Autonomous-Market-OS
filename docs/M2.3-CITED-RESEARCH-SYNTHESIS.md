# M2.3: Cited research synthesis and inspection

Status: implemented and verified offline.

## Current behavior before M2.3

M2.2 returned a structured LightRAG retrieval result and a legacy
`market-os.v1` `ResearchResult`. The legacy summary cited every evidence item
but had no claim-level objects, exact passage support, coverage metric, or
read-only document/passage inspection. M2.3 keeps that frozen result for
compatibility and adds a versioned `market-os.research.v1` synthesis artifact.

## Research contracts

The new contracts live in `market_os/research.py`:

- `DocumentReference`: document identity, publisher/source, published and
  retrieved timestamps, content hash, license, provider, provenance, and
  document-artifact lineage.
- `PassageReference`: exact retrieved text, passage ID/rank, citation ref,
  provider/version, timestamps, passage hash, and retrieval-artifact lineage.
- `Citation`: claim-to-passage-to-document reference with source metadata.
- `ClaimSupport`: exact quote and the supporting passage/citation/document.
- `ResearchClaim`: supported claim with support IDs, citation IDs, document IDs,
  and confidence.
- `UnsupportedClaim`: explicit claim request that has no retrieved support.
- `EvidenceCoverage`: supported/all claim ratio plus passage counts.
- `ResearchSynthesis`: complete deterministic synthesis and fingerprints.

All persisted research records use `market-os.research.v1`. Hashes, timestamps,
cross-references, quote equality, and artifact lineage are validated before
inspection output is returned.

## Deterministic grounding rules

The synthesis strategy is intentionally small: each retrieved passage becomes
one supported claim whose text is exactly the passage text. Each claim has an
exact quote, one citation, one passage, one document, and provider provenance.
If retrieval returns no passages, the objective is recorded as an explicit
unsupported claim with zero coverage. No unsupported fact is promoted to a
supported claim, and no LLM or external model is added.

The LightRAG adapter maps its structured `no_results` response to an empty
retrieval result with an error marker; the workflow still records the
unsupported claim and zero coverage instead of fabricating a passage.

The synthesis fingerprint covers the objective, query, retrieval fingerprint,
claims, unsupported claims, and coverage. Replaying the same persisted
idempotency key returns the same synthesis and backtest payloads.

## Inspection

CLI examples:

```text
market-os inspect <run-id> --resource documents
market-os inspect <run-id> --resource passages
market-os inspect <run-id> --resource claims
market-os inspect <run-id> --resource unsupported-claims
market-os inspect <run-id> --resource passage-claims --id <passage-id>
market-os inspect <run-id> --resource citations --id <claim-id>
market-os inspect <run-id> --resource lineage --id <artifact-id>
```

HTTP inspection is read-only:

```text
GET /v1/runs/<run-id>/research/documents
GET /v1/runs/<run-id>/research/passages/<passage-id>
GET /v1/runs/<run-id>/research/claims/<claim-id>
GET /v1/runs/<run-id>/research/unsupported-claims/<claim-id>
GET /v1/runs/<run-id>/research/passage-claims/<passage-id>
GET /v1/runs/<run-id>/research/citations/<claim-id>
GET /v1/runs/<run-id>/research/lineage/<artifact-id>
```

Inspection never invokes LightRAG or Vibe-Trading. It reads persisted artifacts,
checks artifact SHA-256 values, checks document content hashes, validates the
research contract, and rejects missing artifacts, unknown IDs, or incomplete
lineage.

## Verification and limits

The actual LightRAG and Vibe-Trading offline seams remain in the workflow.
Focused M2.3 tests cover deterministic grounding, unsupported claims, replay,
corrupt hashes, lineage, CLI/API inspection, and paper-only behavior. The
remaining limitation is that deterministic claims are exact retrieved passages,
not semantic summaries; richer synthesis belongs to a later milestone with an
explicit model contract.
