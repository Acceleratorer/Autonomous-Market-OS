# B4.14 Mutation Audit Contract

**Status:** Implemented and verified locally on 2026-10-28 for the synthetic, paper-only local broker.

## Contract

- `submit_order`, `cancel_order`, and `revoke_approval` return typed rejected outcomes for command validation failures that occur after command identity is known.
- Rejected outcomes carry a stable `reason_code`, command identity, `state: rejected`, and the original error text.
- Cancel and approval-revocation rejections append `order.cancel.rejected` or `approval.revoke.rejected` ledger events with the command payload and reason code.
- An identical rejected retry returns the persisted result without appending another event or changing the snapshot.
- Recovery reconstructs the same snapshot and read-only `risk`/`approvals` inspection records.
- A conflicting idempotency payload remains a fail-closed `BrokerRejected` and does not append a second event under the same command key.

## Evidence

Regression coverage is in `market_os/tests/test_portfolio_mutation.py`. The focused B4 matrix covers rejection audit, identical replay, recovery equivalence, inspection visibility, and idempotency conflict behavior.

## Boundary

The Python mutation methods are covered for local paper workflows. CLI and HTTP mutation routes remain disabled. This contract does not add authentication, shared portfolio membership, partial fills, expiry, retention, migration transformation, provider access, live data, trading, deployment, commit, or push.
