# U5.5 Authenticated Connected Web Contract

**Status:** Private single-tenant preview scope and Next.js stack selected on 2026-10-29; deployment and access remain disabled.
**Scope:** Future private, authenticated, read-only web access over the paper API.

## Contract

Before a connected or public browser deployment can be enabled, the system
must define and verify:

- an authenticated subject identity and stable tenant/portfolio audience;
- authorization that maps a subject to permitted portfolio IDs and inspection
  resources;
- a defined subject set for the single tenant and a fail-closed identity
  propagation path from the chosen ingress through Next.js to Python;
- verification of identity assertions and an origin boundary that prevents
  unauthenticated direct access or spoofed principal headers;
- storage isolation per tenant or an equivalent partition boundary;
- same-origin or explicit allow-listed CORS behavior;
- session expiry, revocation, clock handling, and denied-request audit events;
- secret handling outside browser bundles, HTML, manifests, and request logs;
- rate limits, request size limits, timeout behavior, and abuse responses;
- production log retention, alerting, backup/restore, rollback, and operator
  access review;
- a paper-only default where any future mutation capability is separately
  versioned, authenticated, idempotent, audited, and disabled by default.

## Current state

The current gateway is loopback-only, rejects untrusted `Host` headers, and
serves the U5.4 operator shell without authentication. `X-Request-ID` is only
diagnostic correlation; it is not identity, authorization, or a session.
Therefore U5.5 is a documented gate, not a claim that connected access is ready.
The owner selected a private single-tenant preview and Next.js stack, but has
not selected its host or identity provider/login method. These choices do not
authorize a public listener or change the current gateway boundary.

## Promotion criteria

Connected-access implementation may begin only after a concrete deployment
target and identity provider/login method are selected, the single-tenant
storage and portfolio-authorization model is reviewed, and a versioned API/auth test matrix
covers allowed, denied, expired, replayed, forged-principal, direct-origin, and
cross-tenant inspection requests. Session, rate-limit, logging, backup/restore,
rollback, and operator access policies must also be defined for the selected
host. No credentials are required or accepted by the current local shell.
