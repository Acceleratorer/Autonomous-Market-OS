# U5.18 Next.js Bounded BTC Research Inspection

**Status:** Implemented locally on 2026-10-29.  
**Scope:** Add paged, read-only B2/B3 run catalogs and bounded detail pages to the local Next.js operator.

## Contract

- `GET /v1/btc/research/b2/runs` and `/v1/btc/research/b3/runs` accept `limit`
  from 1 to 100 (default 25) and an optional exclusive `after_run_id` cursor.
- Matching detail routes return only a fixed run summary and the B2 metrics or
  B3 report artifact. Unknown query parameters, duplicate fields, invalid
  cursors, and caller-supplied roots are rejected.
- Store roots come from `MARKET_OS_BTC_B2_STORE_ROOT` and
  `MARKET_OS_BTC_B3_STORE_ROOT`; otherwise they resolve under the workflow root
  as `btc-b2` and `btc-b3`. Missing stores are treated as empty and are not
  created by inspection.
- Catalogs page at most 100 sorted run IDs. Each manifest is capped at 256 KiB;
  the selected result artifact is capped at 256 KiB and its exact bytes must
  match the manifest's size and SHA-256 before parsing.
- Responses omit artifact paths, full arrays, prediction rows, feature rows,
  labels, fixture cases, and provider responses. B2 score counts must match the
  run's test sample count. B3 inspection checks dataset, feature, fixture, and
  experiment lineage; requires identical matched inputs and zero network and
  provider requests; and preserves the `not-promoted` decision.
- The Next.js pages render existing persisted runs only. They do not execute or
  replay an experiment. Full replay remains the complete run-integrity check.
- `MARKET_OS_API_PORT` may select a different local gateway port for the
  server-side Next.js fetch; the hostname remains `127.0.0.1` and the default
  port is 8787.

## Design

The `/experiments` catalog switches between B2 numerical baselines and B3
recorded-response comparisons. Detail pages show B2 raw/calibrated test
metrics, or B3 test coverage, matched-control estimates, experiment definition,
offline source counts, and promotion boundary. Empty B1 test sets remain
explicitly unavailable rather than displaying fabricated scores.

The UI reuses the local operator's dark, dense, keyboard-scrollable tables and
uses server-rendered GET navigation. The selected engine has an accessible
current-page state. Tables scroll within their labelled region on narrow
screens. No client fetch state, chart, animation, or new UI dependency is
introduced.

## Verification

The focused BTC research and operator API group passed 29 tests. Next.js
typecheck and production build passed. A production browser smoke exercised B2
pagination and detail, B3 detail, unavailable-fixture messaging, the offline
request and promotion boundaries, and desktop/mobile layout. At 375 px, the
document stayed 375 px wide and the 341 px table region contained the 1,205 px
B2 and 698 px B3 tables. All 61 browser requests stayed on loopback and there
were no console errors. Screenshots are in `output/playwright/u5-18/`.
