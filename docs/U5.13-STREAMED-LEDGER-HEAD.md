# U5.13 Streaming Ledger Head Validation

**Status:** Implemented and measured locally on 2026-10-29.  
**Scope:** Check a recovered broker's ledger head by streaming full-file UTF-8 validation and retaining only the candidate JSONL line.

## Contract

`_ledger_head()` reads text in 64 KiB chunks and validates UTF-8 across the
full file. It retains the candidate final non-empty line for JSON parsing.
Permitted leading JSON whitespace may be dropped; whitespace within a record
is preserved so chunk boundaries cannot change JSON validity or hide a changed
fingerprint. Whitespace-only lines are skipped without retaining their full
contents, including long Unicode whitespace lines. Memory scales with the
largest non-empty line, not the full ledger. The current JSONL format has no
maximum line length, so a single very large record or same-line trailing
whitespace run can still use substantial memory. It supports LF, CRLF/CR, a
missing final newline, trailing blank lines, and records spanning multiple
chunks. A missing or empty ledger still yields the zero fingerprint. Decode,
JSON, missing-field, and filesystem errors continue to fail closed.

Cold recovery still replays every ledger record and verifies the full chain and
checkpoint. Freshness checking remains linear in file size to detect invalid
UTF-8 anywhere in the ledger, but it no longer materializes the full text and
line list in memory. Only the final record is parsed as JSON.

## Verification

- Regression tests reject full-file `Path.read_text()`, reject invalid UTF-8
  in an earlier record, raw tab corruption at a 64 KiB boundary, and invalid
  non-JSON whitespace before a record. They also cover a multi-chunk record,
  CRLF, and 1 MiB of trailing whitespace after a blank line, on the record's
  line, and on a Unicode whitespace-only line. Same-line whitespace remains
  intact through JSON parsing. Existing malformed-ledger tests still pass.
- Focused broker, shared-portfolio, operator, U5 acceptance, and
  application-surface tests: 60 passed.
- On a local synthetic harness with 100 records (3.48 MB), compact summary
  median changed from 5.47 ms to 4.44 ms. Run-to-run cold recovery timings
  varied materially; this is a diagnostic sample, not a CI threshold.
- Python compile check, evidence JSON parsing, and `git diff --check` passed.

## Remaining limits

Catalog enumeration still visits every portfolio directory; the first page
sorts all eligible names, and later pages sort only names after the cursor under
U5.14. Each selected portfolio still requires full validated cold recovery.
Ledger freshness decoding, risk/approval/ledger totals, cursor checks, and page
selection remain linear scans. Avoid trusting a cache or sidecar index until
its integrity, invalidation, and rebuild rules are explicit.
