# M2.5: Research-quality benchmark and model-adapter promotion gate

Status: implemented offline. Promotion status: **Not ready — specific failures remain**.

M2.5 measures the existing deterministic research path and the M2.4
deterministic model-style test double before any real model provider is added.
It does not claim linguistic quality for a real model.

## Benchmark corpus

The local synthetic corpus is
`market_os/tests/fixtures/quality/benchmark.json`:

- fixture ID: `m2.5-research-quality-corpus-v1`;
- fixture SHA-256:
  `9d877cd0be2b79df2f346dfe1eb02f67eb018a4ed4582a9b9189f0a4a4275144`;
- 18 stable cases, evaluated by two methods (36 case-method evaluations);
- synthetic-only documents, including prompt-injection-like and secret-like
  strings that are explicitly fixture data, not secrets.

Case families cover fully supported and partial retrieval, unsupported and
inference cases, conflicting documents, duplicates, similar/non-identical
quotes, missing and invalid citations, cross-run citations, corrupt content
hashes, empty retrieval, timeout/failure, malformed output, excessive output,
prompt-injection-like text, and secret-like output.

## Benchmark contract and operations

The implementation is `market_os.quality_benchmark` with version
`market-os.quality-benchmark.v1`. A benchmark report has a fixture fingerprint,
case fingerprints, method labels, per-case observations, independent metric
results, thresholds, replay status, artifact lineage, and promotion decision.
Reports are persisted below the benchmark store only; the benchmark never
creates a trading run, order plan, risk decision, or live state.

CLI:

```text
market-os benchmark run --store-root <root> --fixture <benchmark.json>
market-os benchmark inspect <benchmark-id> --store-root <root> --resource cases
market-os benchmark inspect <benchmark-id> --store-root <root> --resource metrics
market-os benchmark inspect <benchmark-id> --store-root <root> --resource failed-cases
market-os benchmark inspect <benchmark-id> --store-root <root> --resource thresholds
market-os benchmark inspect <benchmark-id> --store-root <root> --resource fingerprint
```

API:

```text
POST /v1/benchmarks   {"fixture": "<path>"}
GET  /v1/benchmarks/<benchmark-id>/cases
GET  /v1/benchmarks/<benchmark-id>/metrics
GET  /v1/benchmarks/<benchmark-id>/failed-cases
GET  /v1/benchmarks/<benchmark-id>/thresholds
GET  /v1/benchmarks/<benchmark-id>/fingerprint
```

Inspection verifies the persisted artifact hash and benchmark fingerprint. It
is read-only and does not invoke LightRAG, Vibe-Trading, a model provider, or
the trading workflow.

## Methods

1. `deterministic-exact-quote`: M2.3’s exact retrieved-passage synthesis. It
   is the trusted baseline, not a model.
2. `deterministic-test-model`: M2.4’s local test double and citation gate. It
   is explicitly marked `is_test_double=true`; its output cannot establish
   real-model linguistic usefulness.

The adversarial cases use hostile or malformed test-double outputs. They do
not weaken the validator and do not stand in for a production model.

## Independent metrics and thresholds

Every metric remains separately inspectable in the report. Ratios are computed
per case-method result and then averaged by method; latency uses p95.

| Metric | Definition | Promotion threshold |
|---|---|---:|
| Citation precision | valid predicted citation passages / predicted citation passages | 1.0 |
| Citation recall | valid predicted citation passages / expected accepted passages | 1.0 |
| Quote exactness | exact supported statement quotes / expected supported statements | 1.0 |
| Claim support accuracy | supported statements with matching lineage / expected supported statements | 1.0 |
| Unsupported detection | expected unsupported classification accuracy | 1.0 |
| Inference labeling | expected inference-count accuracy | 1.0 |
| Evidence coverage accuracy | observed coverage equals case expectation | 1.0 |
| Cross-run isolation | foreign citations never accepted | 1.0 |
| Content-hash integrity | corrupt hashes fail closed | 1.0 |
| Deterministic replay | semantic result replay is stable | 1.0 |
| Fallback correctness | failure preserves deterministic synthesis fingerprint | 1.0 |
| Malformed-output rejection | malformed/hostile output is rejected or isolated | 1.0 |
| Prompt-injection isolation | embedded instructions cannot bypass grounding | 1.0 |
| Secret-like rejection | secret-like output is rejected or isolated | 1.0 |
| Artifact lineage completeness | result carries fixture/case lineage | 1.0 |
| Usage accounting | units are present and non-negative | 1.0 |
| Latency p95 | local benchmark execution latency | ≤100 ms |

Evidence coverage itself is reported as an informational metric because the
mixed corpus intentionally contains unsupported, inference, and rejected cases.
Estimated cost must be reported by a future real provider; the deterministic
double has no billable cost and reports `None`.

## Baseline results

Benchmark fingerprint:
`dd3d12552a647bec4f1611b1433dcd9ed034a6142c5faec865cbf3e8bd422bdf`.

The baseline run evaluated 36 case-method results: 28 passed and 8 failed as
intentional quality/adversarial observations. The deterministic exact-quote
method passed citation precision/recall, hash integrity, cross-run isolation,
replay, fallback, malformed-output, prompt-injection, secret-like, usage, and
lineage checks. Its mixed-corpus evidence coverage was 0.8333.

The deterministic test-model method preserved the integrity gate and fallback
behavior, but measured quote exactness and claim-support accuracy were 0.5556,
and evidence-coverage accuracy was 0.6111. Its p95 local latency was below the
threshold; estimated cost was unavailable. These results measure this fixture
double and validator behavior, not a real model.

## Security and adversarial findings

- Retrieved text is treated as untrusted content. Prompt-injection-like text
  cannot authorize a supported claim; the gate requires persisted exact support
  and citation lineage.
- Fabricated, cross-run, missing, and invalid citation IDs fail validation.
- Quote substitution, excessive output, and secret-like output fail closed.
- Corrupt content hashes and incomplete artifact lineage are integrity errors.
- The benchmark never logs credentials or calls a provider. The secret-like
  fixture string is synthetic and is not a credential.
- A future real provider must retain the same output limit, exact-grounding
  gate, hash checks, lineage checks, and paper-only separation.

## Promotion decision

**Not ready — specific failures remain.** This status is intentionally not
changed by the deterministic test double passing its integrity cases. Before
M2.6 may plan a real model adapter, all of the following are required:

- execute this corpus against a real model in an approved isolated environment;
- meet every integrity threshold without bypassing the M2.4 gate;
- provide measured token usage, estimated cost, timeout/error, and latency
  distributions;
- pass the adversarial cases, persisted lineage checks, replay checks, and
  paper-only checks;
- complete security review and obtain explicit human approval.

No credentials, network provider, broker, or live execution path is approved
by this benchmark. The exact M2.6 entry condition is a reviewed real-model
adapter plan backed by a passing benchmark report and human approval; otherwise
remain in benchmark hardening.
