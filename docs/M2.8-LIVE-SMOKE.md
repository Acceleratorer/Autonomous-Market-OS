# M2.8: Approval-gated single synthetic OpenAI live smoke

Status: **Pending approval — offline preparation complete, no live request made**.

## Scope and stop condition

M2.8 prepares exactly one bounded OpenAI Responses API request over the local
synthetic ETF/document fixture. It validates transport, response parsing, usage
reporting, citation-preserving grounding, redaction, timeout/error handling, and
deterministic fallback. It does not evaluate investment quality, authorize a
trade, connect a broker, or change paper-only policy.

No provider request was made during preparation. The live request remains behind
two separate gates: the existing adapter approval configuration and the explicit
execution-only `MARKET_OS_M2_8_LIVE_SMOKE_APPROVED=1` flag. The preparation
command never performs transport.

## Official provider facts checked 2026-10-16

- The target model is `gpt-6.1-sol`; the official model page lists Responses
  API support, structured outputs, US/EU data residency, and standard text rates
  of $2.00 per million input tokens and $10.00 per million output tokens.
- The endpoint is `POST https://api.openai.com/v1/responses`. The request uses
  the documented `model`, `instructions`, `input`, `text.format`,
  `max_output_tokens`, and `store:false` fields.
- Responses usage reports input and output token fields. The adapter preserves
  missing usage as unknown and estimates cost only when both counts are present.
- OpenAI documents that API data is not used to train models without explicit
  consent. The Responses endpoint has 30-day abuse-monitoring retention and
  application-state behavior depends on `store` and account controls; account
  eligibility must be confirmed before execution.
- OpenAI documents `Retry-After` for temporary rate-limit or overload responses.
  M2.8 permits zero retries, so any such response ends the smoke safely.

Sources: [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol),

## Synthetic request and hard bounds

The request uses only `market_os/tests/fixtures/lightrag/corpus.json`, labeled
`synthetic-internal`. It contains synthetic SPY/ETF research text, no user data,
secrets, private URLs, live market data, broker instructions, accounts, or order
requests. The prepared payload fingerprint and lineage are recorded in
[`docs/evidence/m2.8-live-smoke.json`](evidence/m2.8-live-smoke.json).

| Control | M2.8 value |
|---|---:|
| Provider | OpenAI Responses API |
| Model | `gpt-6.1-sol` |
| Destination | `https://api.openai.com/v1/responses` |
| Logical requests | exactly 1 |
| Retries | 0 |
| Input bound | 16,000 bytes |
| Output bound | 512 tokens; existing 16,384-character gate |
| Timeout | 20 seconds |
| Spend ceiling | $0.02 USD |
| Storage | `store:false`; raw response not persisted |
| Tools/concurrency | none / none |
| Fallback | deterministic M2.3 synthesis |

## Offline validation

The local harness is `scripts/m2_8_live_smoke.py`:

```text
python scripts/m2_8_live_smoke.py
```

It validates the synthetic payload and writes redacted pending evidence without
opening a network connection. `--execute` is intentionally separate and first
requires `MARKET_OS_M2_8_LIVE_SMOKE_APPROVED=1`; it is not part of ordinary CI.

Focused tests cover configuration, missing approval, exact request/retry/spend
bounds, synthetic classification, payload size, redaction, no-network default,
and pending evidence. The existing M2.7 recorded fixtures cover parsing,
citations, unsupported claims, inference labels, secret-like output, malformed
output, timeout, provider errors, replay, usage unknowns, and deterministic
fallback.

Validate the recorded gate separately with:

```text
python scripts/ci_checks.py validate-m2-8-evidence
```

## Result contract after approval

The live result must parse as `ModelOutput`, pass the existing citation and exact
quote gate, preserve document/passage lineage and hashes, reject unsupported or
secret-like output, remain within output limits, and leave paper-only state
unchanged. A transport success with a rejected grounding result is recorded as
transport success plus deterministic fallback; it is not model success.

Evidence stores only provider/model, timestamps, elapsed time, status, usage,
estimated cost, retry count, safe response metadata, fingerprints, gate results,
and redaction/retention metadata. It never stores API keys, authorization
headers, raw request text, raw response text, or private environment values.

## CI and manual execution

Existing CI and security workflows remain credential-free and offline. They do
not invoke `--execute`, read provider credentials, or run a live smoke on pushes
or pull requests. A future manual invocation must use the explicit approval flag,
an approved environment, the exact bounds above, and a human-reviewed command;
there is no automatic workflow dispatch in M2.8.
