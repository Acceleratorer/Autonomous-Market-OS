# U5.8 Local Next.js Operator Web

**Status:** Implemented locally on 2026-10-29.  
**Scope:** Owner-selected TypeScript, React, Node.js, Next.js, and Tailwind CSS
operator for local synthetic paper portfolios.

## Decision

Use a separate Next.js App Router application at `apps/web/next-operator/` for
the local portfolio inspection workflow. The app is a Node.js server bound to
`127.0.0.1:3000`. It reads the existing Python gateway at
`127.0.0.1:8787`; Python remains the owner of portfolio identity, accounting,
risk, reservations, recovery, and persistence.

The selection is local-only. It does not choose a shared deployment target,
identity provider, storage isolation model, or authenticated connected runtime.
Those remain U5.5 promotion inputs.

## User-visible routes

- `/` lists validated local portfolios and shows gateway availability.
- `/portfolios/<portfolio-id>` displays the validated portfolio summary,
  identity context, reservations, orders, and recent risk audit records.
- Invalid and unavailable responses use bounded, generic status messages; raw
  backend errors are not rendered.

All route data is fetched server-side with GET, `cache: "no-store"`, omitted
credentials, redirect rejection, a four-second timeout, runtime shape checks,
and portfolio identity matching. The UI submits no commands and derives no
financial metrics from the API values.

## Design and security constraints

- Keep the interface dense, calm, responsive, and legible for operational
  inspection. Use the page-specific design brief in
  `design-system/autonomous-market-os/pages/dashboard.md`.
- Keep motion minimal; no decorative animation is needed for this read-only
  surface. Respect reduced-motion preferences.
- Keep server components as the default and keep the API origin fixed to the
  loopback gateway. Do not expose credentials or domain logic to browser code.
- Apply a per-request nonce Content Security Policy and browser hardening
  headers in the Next.js proxy.
- Preserve separate static preview and compatibility-shell surfaces.

## Local run

Start the Python gateway from the repository root:

```powershell
python -m apps.gateway --host 127.0.0.1 --port 8787
```

Then run the web application from `apps/web/next-operator/`:

```powershell
npm ci
npm run dev
```

Open `http://127.0.0.1:3000`. See `apps/web/README.md` for the full local
workflow.

## Verification

The milestone is promoted only with a committed package lock, dependency
review, TypeScript check, production build, and real-browser smoke against the
loopback gateway. The gateway smoke uses a temporary synthetic paper portfolio
and never reads or modifies the developer's default `.market_os` store.
The recorded browser smoke covered the registry and detail routes at 1440px and

## Remaining gates

- U5.5: choose a connected deployment target, identity provider, storage
  isolation model, session rules, and production observability before shared
  access is enabled.
- B4: retention deletion and schema transformation remain explicit future
  contracts; the local UI does not bypass them.
- U5.9 and [U5.10](U5.10-BOUNDED-MEMBERS-RESERVATIONS.md) bound order, risk,
  membership, and reservation pages for the local browser detail surfaces. The
  v1 aggregate, legacy resources, and catalog remain compatibility routes;
  broker recovery and risk-page selection remain linear in ledger size.
- The legacy `/risk` resource still returns the full audit history for local
  compatibility and must not be exposed through a shared or remote service.

No credentials, public listener, mutation endpoint, live venue, or live-trading
path is introduced by U5.8.
